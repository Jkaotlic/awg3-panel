# Подбор маскировки на Keenetic

Панель переносит механизм `find-junk` из AWG Manager v2.20.6 на один
выделенный тестовый туннель. Она генерирует `Jc/Jmin/Jmax` вместе с
`I1–I5`. Можно выбрать QUIC Initial, DNS, SIP, STUN, DTLS, случайный
профиль или вариант без CPS. Для профилей с именем хоста доступны
стандартный, российский, CDN и пользовательский пулы. Домен, который
попал в сгенерированный пакет, отображается у попытки.

Первым проверяется текущий профиль тестового туннеля. Затем панель перебирает
до 10 новых вариантов по умолчанию. Лимит можно изменить от 1 до 30.
Каждый вариант получает три отдельных запуска. Успех подтверждают свежее
рукопожатие, две HTTP-проверки и двусторонний трафик через тестовый интерфейс.
Панель рекомендует вариант по числу успешных запусков, при равенстве
сравнивает среднее время успешных проверок. Перебор останавливается, как
только новый вариант достигает заданного порога (95% по умолчанию).

У Cloudflare WARP выборка состоит из адресов WARP. Здесь замеры идут
через принадлежащий оператору AWG-сервер с фиксированным endpoint.
[Механизм AWG Manager](https://github.com/hoaxisr/awg-manager/blob/v2.20.6/internal/warpscout/findjunk.go)

## Привязка

1. Выделите в панели отдельный включённый тестовый пир. Скачайте его обычный
   `.conf` и импортируйте в AWG Manager. Используйте совместимый с AWG 3.1
   туннель с бэкендом `kernel`.
2. Остановите тестовый туннель. Отключите его использование маршрутом по
   умолчанию, привязки к клиентам, DNS и политикам доступа, внешние
   обфускаторы и мониторинг с авторестартом. Сохраните клиентский
   `AllowedIPs = 0.0.0.0/0` и штатную HTTP-проверку доступности.
   Уберите также привязки из внешних скриптов и политик. На время замеров
   воздержитесь от ручных изменений этого туннеля в AWG Manager.
3. Дайте сервису панели доступ к AWG Manager по доверенной сети управления.
   Используйте HTTPS или локальный HTTP-адрес. Разместите REST-ключ и
   отдельный MCP-ключ AWG Manager в двух файлах, доступных только владельцу
   сервиса. Для полного подбора REST меняет `Jc/Jmin/Jmax` и `I1–I5`,
   а MCP запускает, проверяет и останавливает тестовый туннель.
4. Передайте настройки в окружение сервиса `awg3panel`, например через
   `EnvironmentFile` в systemd drop-in. После добавления настроек перезапустите
   панель. При изменении конфигурации сначала дождитесь завершения подбора.

| Переменная | Значение |
| --- | --- |
| `AWG3PANEL_TUNE_URL` | Адрес AWG Manager, например `https://router.example.com` |
| `AWG3PANEL_TUNE_IFACE` | ID серверного интерфейса в панели |
| `AWG3PANEL_TUNE_PEER` | ID тестового пира из ссылки на его клиентский конфиг |
| `AWG3PANEL_TUNE_REST_TOKEN_FILE` | Путь к файлу с REST-ключом для чтения состояния и изменения восьми параметров тестового туннеля |
| `AWG3PANEL_TUNE_MCP_TOKEN_FILE` | Путь к файлу с отдельным MCP-ключом |
| `AWG3PANEL_TUNE_TUNNEL` | ID тестового туннеля в AWG Manager |
| `AWG3PANEL_TUNE_TUNNEL_NAME` | Точное имя того же туннеля |
| `AWG3PANEL_TUNE_ENDPOINT` | Точный `Endpoint` импортированного пира, например `203.0.113.20:3478` |
| `AWG3PANEL_TUNE_ROUTE` | Ожидаемый маршрут AWG Manager. Если переменная пуста, допускается автоматический или заданный в туннеле прямой WAN. Для точной привязки укажите `auto`, `wan:<интерфейс>` или `tunnel:<id>` |
| `AWG3PANEL_TUNE_CPS_BRIDGE` | `1` для закрытого моста ниже. Пустое значение использует REST напрямую с проверкой схемы AWG Manager v2.20.6 |

### Закрытый мост для AWG Manager в локальной сети

Если панель соединяется с AWG Manager через закрытый SSH-проброс, замените
скрипт на стороне локальной сети копией [keenetic-tune-bridge.py](../deploy/keenetic-tune-bridge.py)
и добавьте в его существующий приватный каталог файл `tunnel-name` с
точным именем тестового туннеля и правами `0600`. Скрипт запускается
командой `python3 keenetic-tune-bridge.py PRIVATE_CONFIG_DIRECTORY`.
Он слушает только `127.0.0.1:12224`. Проброс со стороны панели слушает
`127.0.0.1:12222`. Укажите панели этот локальный URL и
`AWG3PANEL_TUNE_CPS_BRIDGE=1`. Мост принимает запись ровно восьми полей
для одного привязанного туннеля, сверяет его состояние и переносит
служебные параметры напрямую в LAN. Секреты AWG Manager остаются на
локальной стороне моста.
Если в AWG Manager включена авторизация, положите его REST API-ключ в
`upstream-rest.token` с правами `0600`. Мост использует его для запросов
к AWG Manager. Через мост доступен прямой WAN (`auto` или `wan:<интерфейс>`).
Маршрут `tunnel:<id>` доступен при прямом REST.

## Запуск

Откройте **Автоподбор Keenetic** и проверьте имя тестового туннеля.
Оставьте его выключенным в AWG Manager и нажмите **Начать проверку**.
Для первого запуска достаточно настроек панели. Профиль, пул доменов,
лимит и порог можно задать в **Дополнительных параметрах проверки**.

Панель покажет исходный профиль тестового туннеля и новые варианты,
число успешных запусков и среднюю задержку. По завершении можно
скачать конфиг выбранной попытки. Замер относится к провайдеру и
маршруту привязанного Keenetic.

После завершения, отмены или тайм-аута панель возвращает исходные
`Jc/Jmin/Jmax` и `I1–I5` и оставляет тестовый туннель выключенным. Если связь потерялась
или процесс остановился, панель читает журнал и пробует восстановить
исходное состояние при следующем запуске подбора. При постороннем изменении
туннеля автоподбор останавливается до ручной проверки.

Выберите завершённый рабочий вариант. **Скачать .conf попытки** собирает
файл сразу. **Сохранить в тестовый профиль** записывает тройку и все пять
CPS-полей в профиль тестового пира. Можно заранее включить автоматическое
сохранение рекомендации после завершения. После штатной отмены доступны
уже завершённые варианты.

Для другого пира на том же интерфейсе откройте его карточку по имени в
списке пиров. Нажмите **Настроить → Подставить вариант с Keenetic**.
Панель заполнит `Jc/Jmin/Jmax` и `I1–I5` из последней рекомендации,
если она указывает на новый измеренный вариант. Проверьте поля, сохраните
изменения и скачайте конфиг этого пира. Проверьте связь на его устройстве.

Для ручного сравнения разверните **Сравнить на устройстве клиента** в
карточке нужного подключения и скачайте оба файла. Эталон A — текущий
`.conf`. Вариант B сохраняет адрес, ключи и сервер. Если в A есть
`I1–I5`, B убирает только эти поля. В остальных случаях B переключает
мусорные пакеты. Изменения действуют в скачанном варианте B.

Включайте A и B по очереди на устройстве клиента в одной сети и повторяйте
те же действия, например подключение к VPN и открытие нужного сайта.

На вкладке **Новый интерфейс** можно подготовить серверный и клиентский
черновики. Там доступны ручная тройка J, профиль и пул CPS, таймеры
Rekey/Keepalive, `ContentPaddingAddition`, `DisableCookies` и
`RandomTrailers`. Для копирования выберите рабочего пира с доступным
клиентским профилем. Черновик копирует его клиентские настройки и
генерирует согласованные `S/H` и ключ защиты заголовка для нового
комплекта. Используйте эту пару по обе стороны нового туннеля.
На стороне Cloudflare WARP используются штатные `S1–S4` и `H1–H4`.
Серверы Cloudflare WARP могут отбрасывать пакеты с `RandomTrailers`.
