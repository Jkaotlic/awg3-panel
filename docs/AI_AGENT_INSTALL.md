# Агенту: установка awg3-panel на чистый VPS

Работай по [install.md](install.md) и ограничениям проекта. Установщик создаёт новый
AWG3.1 userspace интерфейс и подключает свою панель. Веб-демон по-прежнему меняет
только peer-ы; не расширяй его полномочия ради bootstrap.

## Входные данные

Подтверди конкретный целевой сервер и SSH-доступ, разрешение установки и окно
перезагрузки, если она потребуется. Новый VPS не определяется по старой записи
памяти. Разрешение подготовить код/файл не означает разрешение менять production.
Если установка уже явно разрешена для этой цели, не спрашивай подтверждение на
каждый обратимый шаг.

Проверь Ubuntu24.04/Debian13, amd64, systemd, /dev/net/tun, маршруты и порт3478.
Получение root по SSH не является поводом менять password-auth или SSH-порт.
Нужна консоль провайдера и желательно снимок чистой VM. На занятом хосте не
удаляй конфликтующие интерфейсы, цепочки, файлы и контейнеры ради установки.

## Комплект и секреты

Собирай на доверенной машине через Dockerfile.build или скачивай проверенный релиз из официального репозитория. Передавай комплект по
SCP вместе с внешним .tar.gz.sha256. До распаковки и запуска install.sh проверь
`sha256sum -c awg3panel-linux-amd64.tar.gz.sha256` в каталоге архива.
Оба файла должны происходить из доверенной сборки и передаваться по защищённому
каналу; скачанный рядом checksum сам по себе не доказывает авторство.
PAT, private keys и пароли не помещай в argv, URL, чат, shell xtrace или CI
logs. Сгенерированные конфиги, ключи и пароли не публикуются.

SHA256SUMS — проверка целостности, не независимая подпись издателя. Перед
исполнением payload установщик отвергает несовпадение хешей, лишние файлы и
симлинки. Не переходи на скачивание mutable latest при ошибке проверки.

Вывод команды установки включает только пути. Первый профиль и пароль находятся
в root-only файлах; не вызывай cat и QR в транслируемый журнал. При передаче
пользователю сообщай приватный путь к файлу, а не его содержимое.

## Выполнение

1. Прочитай dry-run с настоящими endpoint/subnet/egress. Он не должен писать
   файлы, ставить пакеты и менять сеть.
2. Запусти ту же команду без dry-run. Не глуши ошибки через `|| true`.
3. При обрыве повтори тот же комплект и аргументы. Manifest и staging отвечают
   за продолжение; не удаляй их для «исправления» ошибки.
4. На успехе проверь doctor, службы и правильный внешний firewall. Внутренний
   HTTP401 — проверка аутентификации, а не доказательство внешнего VPN-доступа.
5. Передай файлы профиля/доступа безопасно и организуй внешний клиентский тест.

Первый и все последующие профили выпускаются штатным issuer. I1 уже генерируется
автоматически: не заменяй его общей статичной строкой. I2 берётся из проверенного
DTLS-шаблона; поля 3.1/таймеры переносятся из сервера. Общие S/H/HPK на production
не меняются; новая установка всегда получает собственные ключи и полосы H.

## Верификация

Проверь точный endpoint, сервис/процесс и загруженный userspace backend. Не путай
версию установленного kernel-модуля с реально работающим amneziawg-go. Порт из
ss, свежий handshake и зелёный doctor по отдельности недостаточны.

Нужны RX/TX при действиях клиента, открытие сайтов/крупная передача, DNS,
простой/повтор и проверка после разрешённой перезагрузки. Стартовый профиль
IPv4-only: IPv6/KillSwitch проверяются на клиенте. Если доступа к нужной сети нет,
напиши «сервер проверен, клиентская проверка на операторе X ожидается», не «всё
работает». Не сканируй посторонние endpoints вместо адреса пользователя.

Используй field-selectors latest-handshakes/transfer/listen-port. Полные awg
show/showconf/dump и журналы ошибок могут содержать ключи; сначала защищённое
локальное чтение и редакция, затем минимальный отчёт.

## Откат и отчёт

Runtime rollback делает согласованный защищённый архив, останавливает свои
службы/правила и сохраняет ключи/конфиги для восстановления. Он не удаляет пакеты,
не сбрасывает чужой firewall и не выключает forwarding. Для полного возврата
системы нужен исходный snapshot. Не подменяй этот путь rm -rf/iptables flush.

Отчёт: цель, версия/хеш комплекта, что создано, результаты server/client тестов,
защищённые пути к профилю/бэкапу и непроверенные ограничения. Production-публикация,
push/merge и развёртывание на прежних VPS — отдельные действия по заданию.
Не сохраняй ключи и сырые логи в Git или память.
