# Установка учебного стенда

Этот путь предназначен для **чистого Ubuntu 24.04 или Debian 13, Linux amd64,
systemd и /dev/net/tun**. Исходники и готовые сборки публикуются в GitHub. Сгенерированные ключи и пароли остаются приватными.
Действующую чужую установку или работающий сервер поверх неё установщик не мигрирует.

## Что получится

- Userspace AmneziaWG 3.1, без DKMS и Docker на VPS.
- Default personal-stun-v1: UDP3478, STUN+DTLS, MTU1280, J6/48/160,
  padding10-100, равные S, узкие непересекающиеся H и рабочие диапазоны таймеров.
- Новые серверные и клиентские ключи. Персональный I1 создаёт существующий issuer
  автоматически; отдельную кнопку генерации нажимать не требуется.
- Первый административный профиль и сильный пароль — в файлах 0600 на VPS.
- Панель доступна внутри VPN; публичного HTTP-порта или зависимости от домена нет.

Этот профиль предназначен для сетевых экспериментов и не гарантирует доступность во всех сетях.
DisableCookies включён как в образце: это осознанный компромисс защиты от
handshake-flood. Поведение может различаться между операторами и клиентами.

## 1. Получить готовую сборку

Откройте [последний релиз](https://github.com/Jkaotlic/awg3-panel/releases/latest).
Архив собран GitHub Actions и прошёл тесты/сканирование до публикации.
Для установки напрямую с сервера используйте простой установщик из раздела 3.
GitHub-токен на сервере не требуется.

Для ручного переноса скачайте `awg3panel-linux-amd64.tar.gz` и
`awg3panel-linux-amd64.tar.gz.sha256` из одного релиза. Проверяйте checksum до
распаковки. SHA256 проверяет целостность; доверие к источнику опирается на HTTPS
и выбранный репозиторий, а не на сам файл checksum.

При самостоятельной сборке на доверенной машине с Docker:

```powershell
$releaseVersion = git rev-parse --short=12 HEAD
docker build --build-arg "VERSION=$releaseVersion" -f deploy/Dockerfile.build --target artifact --output type=local,dest=dist .
```

Собственная сборка создаёт архив с VERSION в имени. Не переименовывайте его
без пересоздания внешнего checksum. Исходники движка/инструментов и их зависимости
закреплены в `deploy/engine.lock` и `deploy/enginebuild/`.

## 2. Подготовить VPS

Рекомендуемый старт: KVM amd64, 2 vCPU, 2 ГБ RAM, 20 ГБ SSD, публичный IPv4.
Проверь SSH во втором окне и наличие консоли провайдера. Сделай снимок новой VM.
Внешний firewall провайдера должен пропускать UDP3478 и фактический SSH-порт.

Нужны базовые iproute2 и util-linux (`ip`, `ss`, `flock`). В минимальном образе:

```bash
apt-get update
apt-get install -y iproute2 util-linux
```

Curl, iptables и procps (sysctl) установщик доставит, если их нет. Он не отключает SSH-пароли,
не меняет SSH-порт, не удаляет пакеты и не сбрасывает имеющийся firewall.
При конфликте с интерфейсом, портом, подсетью, файлами или цепочками он откажет.
Активные UFW/firewalld/nftables требуют отдельной ручной интеграции; bootstrap
их не отключает и не пытается обойти.
Остановись и разберись с конфликтом; не удаляй чужие ресурсы по подсказке вслепую.

## 3. Установить

Подключитесь к серверу по SSH и выполните:

```bash
curl -fsSLo install.sh https://github.com/Jkaotlic/awg3-panel/releases/download/v0.2.0/install.sh
sudo bash install.sh --version v0.2.0
```

1. В панели хостинга найдите **публичный IPv4** вашего VPS. Введите его в мастер
   без порта. Если мастер уже предлагает правильный адрес, нажмите Enter.
2. Дождитесь проверки. Если она нашла конфликт, исправьте указанную причину
   и запустите мастер повторно. Пакеты и службы на этом этапе ещё не меняются.
3. На вопрос об установке ответьте `да`. Пустой ответ отменяет установку.
   Если у хостинга включён сетевой экран, разрешите входящий **UDP 3478**.
4. После сообщения «Готово» перейдите к первому подключению ниже.

Для автоматизации и повторяемых запусков используйте явный адрес:

```bash
sudo bash install.sh --endpoint PUBLIC_IPV4 --dry-run
sudo bash install.sh --endpoint PUBLIC_IPV4
```

Обеим командам можно передать одинаковый `--version vX.Y.Z` с тегом нужного релиза.

Исходный комплект сохраняется в `/var/lib/awg3panel-installer/SHA256/bundle`.
Этот путь выводится при установке. Для отката используйте выведенный путь к
комплекту и [порядок остановки и восстановления ниже](#6-состояние-обслуживание-и-откат).

Для ручного офлайн-переноса отправьте архив и checksum по SCP, затем:

```bash
cd /root
sha256sum -c awg3panel-linux-amd64.tar.gz.sha256
# Продолжать только после OK.
tar -xzf awg3panel-linux-amd64.tar.gz
cd awg3panel-linux-amd64-COMMIT
sudo ./install.sh --endpoint PUBLIC_IPV4 --dry-run
sudo ./install.sh --endpoint PUBLIC_IPV4
```

COMMIT — каталог, полученный после распаковки. Внутри архива находится
пакетный bootstrap; в корне репозитория — загрузчик релиза с тем же именем.

Установщик проверит комплект, выберет исходящий интерфейс и создаст подсеть
10.66.0.0/24. Если она занята, явно выбери другую с **первым адресом хоста**:

```bash
sudo ./install.sh --endpoint SERVER_IP --subnet 10.77.0.1/24
```

Не меняй аргументы при продолжении той же установки. Если egress выбран неверно,
до первого запуска передай `--egress ИМЯ_ИНТЕРФЕЙСА`. За cloud NAT указывай внешний
IPv4, к которому реально смогут подключаться клиенты. Установщик не угадывает
адрес по внешним сервисам и не настраивает провайдерский NAT/firewall.

Чтобы явно указать DNS новым клиентам, до установки добавь `--dns 1.1.1.1,1.0.0.1`.
По умолчанию DNS не задан; при необходимости укажите его явно.
Для нового IPv4-only интернет-профиля выбирай доступный публичный IPv4 DNS:
частные сети и cloud metadata этим firewall не маршрутизируются клиентам.

## Первое подключение

Установщик сообщает **пути**, а не выводит пароли/QR/ключи:

- `/root/awg3panel-admin.conf` — первый профиль;
- `/root/awg3panel-access.txt` — адрес панели, логин и пароль.

Скачайте профиль на свой компьютер. Если ваш SSH-вход под `root`, выполните
**на компьютере**, подставив адрес VPS:

```bash
scp root@PUBLIC_IPV4:/root/awg3panel-admin.conf .
```

Если вы вошли под обычным пользователем с `sudo`, сначала выполните **на VPS**:

```bash
profile_dir=$(mktemp -d "$HOME/awg3-profile.XXXXXX")
sudo install -m 600 -o "$(id -u)" /root/awg3panel-admin.conf "$profile_dir/awg3panel-admin.conf"
printf '%s\n' "$profile_dir/awg3panel-admin.conf"
```

Скачайте выведенный путь по SFTP или SCP под тем же SSH-пользователем. Затем
удалите временную копию на VPS: `rm -- "$profile_dir/awg3panel-admin.conf"`.
Откройте файл доступа в своём SSH-терминале командой
`sudo less /root/awg3panel-access.txt` и нажмите `q`, чтобы выйти.

Храните профиль и пароль в приватном месте. Не отправляйте содержимое в чат,
issue, логи агента или генератор конфигураций. Импортируй первый файл в клиент с
подтверждённой поддержкой AWG3.1, подключись к VPN и открой адрес из файла доступа
(обычно http://10.66.0.1:8081). Новый телефон/ноутбук добавляй в панели: каждому
нужен свой peer. Уже существующий механизм создаст его I1 автоматически, I2 и
остальные параметры наследуются от пресета/сервера.

STUN-персонализация выбирает из ограниченного набора SOFTWARE-полей: два CPS-
описания могут совпасть, а transaction ID движок рандомизирует при отправке.
Уникальность текстовой строки не является отдельной гарантией безопасности.

Начальный профиль включает IPv4 full tunnel. IPv6 хоста не отключается, а IPv6
клиента не блокируется этой настройкой автоматически. Проверь IPv6, DNS и
KillSwitch на устройстве; до такой проверки нельзя заявлять отсутствие утечек.

## 5. Проверить работу

```bash
sudo /usr/local/libexec/awg3panel/doctor
sudo systemctl status awgtop awg3panel --no-pager
sudo /opt/awgtop/bin/awg show awgtop latest-handshakes
sudo /opt/awgtop/bin/awg show awgtop transfer
```

Doctor проверяет владение конфигами, службы, UDP-порт, MTU, forwarding, NAT и
HTTP401 без пароля. Дополнительно с клиента проверь сайты, крупную передачу,
DNS, повтор после простоя, домашнюю/мобильную сети и перезапуск VPS. Handshake
без роста RX/TX и передачи данных не доказывает работоспособность.

После перерыва просто повтори исходную команду из того же комплекта. Ключи,
профили и настройки не перегенерируются. Повтор завершённой установки не является
обновлением: другой бинарник намеренно не заменяет имеющийся молча.

## 6. Состояние, обслуживание и откат

Файлы и контрольные суммы новой установки записаны в root-only
`/var/lib/awg3panel-bootstrap/manifest.json`. Приватные staging-файлы нужны для
продолжения незавершённой подготовки; содержимое ключей в manifest не пишется.
Умолчания клиентов меняются в панели, не в seed-секции `client:` config.yaml.

Ручная правка управляемого серверного Interface/config.yaml вне этого пути
обнаруживается как drift: установщик откажется её затереть. Отдельного автомастера
перенастройки сервера в этой версии нет. Не переписывай manifest для обхода
проверки и не используй переустановку как обновление существующего интерфейса.

### Остановка установленного комплекта

Для отката runtime перейдите в каталог исходного комплекта и выполните:

```bash
sudo bash deploy/rollback.sh --dry-run
sudo bash deploy/rollback.sh --apply
```

В режиме `--dry-run` скрипт проверяет принадлежность конфигурации установке
и описывает предстоящие действия. Режим `--apply` берёт общую с установщиком
блокировку и завершится с ошибкой, если другая операция уже выполняется.

Сначала скрипт останавливает панель для согласованного бэкапа и создаёт архив
`/root/awg3panel-backup-*.tar.gz` с правами `0600`. Затем он отключает
автозапуск обеих служб, останавливает туннель и проверяет отсутствие цепочек
`AWG3P_*` и переходов к ним. Если правила остались после остановки, скрипт
пытается удалить их по метке текущей установки и загрузки. Чужая цепочка с тем
же именем или ошибка проверки firewall приводят к ненулевому коду возврата.
Архив при этом сохраняется, а службы уже могут быть остановлены.

Конфиги, ключи, пакеты, staging и IPv4 forwarding сохраняются. Чтобы снова
запустить эту установку, повторите исходную команду с тем же комплектом
и параметрами. Для отмены всех системных изменений используйте снимок VPS,
сделанный до установки.

### Возврат предыдущей версии панели

Для возврата версии нужен проверенный бинарник предыдущей совместимой версии
и резервная копия конфигурации и состояния. Убедитесь, что эта версия читает
текущий формат данных и поддерживает используемую конфигурацию. Если проверка
совместимости требует восстановления прежнего состояния, сначала проверьте
согласованный бэкап на отдельном стенде. Бинарник с поддержкой только формата
`peers.json` версии 2 отклоняет версию 3. Для возврата к такому бинарнику
нужен согласованный снимок конфига и состояния, снятый до обновления.
Сначала завершите восстановление всех незаконченных операций текущей версией.

Остановите службу панели, сохраните копию текущего бинарника и атомарно
замените `/usr/local/bin/awg3panel` предыдущим бинарником с владельцем
`root:root` и правами `0755`. Затем запустите службу и проверьте её статус,
версию запущенного бинарника и ответ панели. Каталоги `/etc/awg3panel` и
`/var/lib/awg3panel` содержат данные и ключи, необходимые для восстановления.
Если понадобится полный повтор bootstrap, он проверит совпадение файлов с
исходным комплектом уже в `--dry-run`.

Чтобы восстановить только потерянный локальный первый профиль после завершённой
установки, используй сохранённую защищённую копию. Если файла нет и нужен экспорт
через CLI, останови панель, посмотри `awg3panel list`, направь
`awg3panel export ID` в файл с umask077 и запусти панель снова. Команда не создаёт
нового пира. Readonly-сборка не предоставляет этот CLI-путь.

## Границы первой версии

- Linux amd64; ARM64 и другие ОС не заявлены проверенными.
- Только новый userspace AWG-интерфейс со STUN3478. Миграции чужих установок нет.
- Настройка внешнего firewall, DNS/IPv6 клиента и проверка конкретного оператора
  остаются явными шагами владельца.
- Сборка и тесты выполняются в Actions; публикация релиза запускается вручную. Удалённые серверы workflow не настраивает.
- Протокол проверки артефакта: [install-verification.md](install-verification.md).
- Для агентов: [AI_AGENT_INSTALL.md](AI_AGENT_INSTALL.md).
